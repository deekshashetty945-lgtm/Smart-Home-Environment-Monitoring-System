This Week 3 report documents the debugging and performance optimization of a Timer Interrupt Based LED Controller developed using Embedded C. The work is an extension of the Week 2 firmware project and uses a hardware-independent timer and GPIO simulation so that the firmware logic can be compiled and tested on a normal computer. The main objective of the task was to identify a realistic timer-related software issue, understand the fault through systematic debugging, implement a correction, and optimize the firmware without changing its intended behavior.

The debugging activity focused on the timer event condition. An intentionally buggy version used an equality comparison for detecting the timer period. This approach can be unreliable if a timer counter advances beyond the exact threshold. The condition was therefore changed to a greater-than-or-equal comparison, making the event detection more robust. Debug output was also used to observe LED transitions and verify interrupt behavior.

The optimization stage simplified the simulated interrupt flow by removing an unnecessary interrupt flag because the simulation processes the interrupt immediately when the timer period is reached. The code was also organized using static internal functions and a compact timer update operation. Validation was performed using a 1000-tick timer period and a 5000-tick simulation, where five interrupt events are expected. The LED transition sequence and final state were checked against the expected behavior.

The report includes the debugging methodology, identified issue, corrective action, optimized code approach, test cases, validation output, performance discussion, learning outcomes, and conclusion. The accompanying source files provide the buggy, debugged, and optimized implementations for reproducibility and GitHub submission.
